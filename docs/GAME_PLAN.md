# План игры Dinoster Arena

## Почему Phaser

Для первой версии нужен быстрый 2D-результат на компьютере и планшете. Phaser уже даёт игровой цикл, сцены, ввод, масштабирование, звук и Arcade Physics. Это снижает количество собственного инфраструктурного кода и позволяет сосредоточиться на ощущении боя.

Текущий 3D model lab остаётся отдельным проектом для экспериментов с моделями и референсами. Игра не зависит от него.

## Образ результата

Короткий детский arena brawler: игрок управляет динозавром, подходит к сопернику, вовремя атакует, видит понятную реакцию на попадание и выигрывает или проигрывает один короткий раунд.

Первый тест успеха: ребёнок без объяснения понимает управление, заканчивает раунд и хочет сыграть ещё раз.

## Основной цикл

1. Начало раунда.
2. Сближение с соперником.
3. Атака с заметной подготовкой и коротким recovery.
4. Попадание, урон и отбрасывание.
5. KO одного бойца.
6. Победа или поражение.
7. Рестарт одной кнопкой.

## Milestones

| Этап | Результат | Критерий готовности |
|---|---|---|
| M0 — Foundation | Phaser + TypeScript + Vite, адаптивный canvas, Arcade Physics, документы | Проект устанавливается, собирается и показывает стартовую сцену |
| M1 — Movement | Геометрический герой, границы арены, единый слой intent-ввода, клавиатура | Герой предсказуемо двигается влево/вправо и не выходит за границы |
| M1.5 — 2.5D arena | Перспективная геометрическая площадка, движение по X/Y, depth и масштаб по Y | Герой двигается по 2.5D-плоскости, не выходит за её границы и меняет depth/масштаб по Y |
| M2 — Combat dummy | Одна атака, FSM, hitbox/hurtbox, здоровье, hit reaction | Одно нажатие наносит ровно один урон только в active-фазе |
| M3 — Complete round | Простой AI, KO, победа/поражение, рестарт | Раунд можно закончить и начать заново без перезагрузки |
| M4 — Tablet controls | Touch UI, multi-touch, landscape-проверка | На планшете можно одновременно двигаться и атаковать |
| M5 — Character art pass | Утверждение первого героя, оригинальные или лицензированные спрайты и анимации | Владелец проекта подтвердил персонажа, а заглушка заменена без изменения правил боя |
| M6 — Juice | Звук, вспышка, hit-stop или shake, частицы | Каждое попадание ясно читается и ощущается сильным |
| M7 — Expansion | Новые способности и персонажи после проверки базового раунда | Добавляется только то, что подтвердил детский playtest |
| M7.1 — Ranged attack | Снаряд, дальность и cooldown для дальнобойного героя | Выстрел читается, ограничен cooldown и использует общую систему урона |
| M7.2 — Limited flight | Отдельная кнопка полёта, энергия и автоматическое приземление | Полёт ограничен по времени и корректно взаимодействует с атаками и ареной |
| M7.3 — Character roster | Выбор нескольких героев с разными характеристиками | Различия героев понятны ребёнку и не дублируют друг друга |

## Ограничения первого среза

- Только одна арена и один матч.
- Бой проходит на 2.5D-плоскости с движением по X/Y.
- Одна кнопка атаки.
- Один простой противник.
- Без выбора персонажа, комбо и специальных приёмов.
- Геометрические заглушки допустимы до M5.

## Базовые параметры для первого прототипа

Это стартовые значения, а не окончательный баланс:

| Параметр | Значение |
|---|---:|
| Здоровье | 5 попаданий |
| Скорость игрока | 300 px/s |
| Дальность атаки | 120 px |
| Startup | 180 ms |
| Active | 100 ms |
| Recovery | 320 ms |
| Отбрасывание | 220 px/s |
| Длительность раунда | 60–90 s |

Меняй параметры после playtest, а не для маскировки ошибок в состояниях или коллизиях.

## Порядок реализации

Не создавай всю будущую архитектуру заранее. Каждый milestone должен заканчиваться рабочей сборкой и отдельным небольшим PR.

Ближайшая задача после M0:

> Реализуй только M1: добавь геометрическую заглушку игрока и движение влево/вправо через A/D и стрелки. Введи минимальный слой intent-ввода. Ограничь игрока ареной. Не добавляй атаку, AI, touch UI, спрайты и звук.

Критерии M1:

- A/D и стрелки дают одинаковое движение;
- отпускание клавиши останавливает героя;
- одновременные противоположные направления дают нулевой intent;
- герой не выходит за границы;
- скорость не зависит от FPS;
- сборка проходит без ошибок.

Ближайшая задача после M1:

> Реализуй только M1.5: расширь intent-ввод до X/Y, добавь геометрическую 2.5D-площадку, ограничь ею движение и менять depth/масштаб героя по Y. Не добавляй бой, AI, touch UI, ассеты и звук.

Критерии M1.5:

- WASD и стрелки дают одинаковое движение по X/Y;
- диагональное движение нормализовано;
- противоположные направления по одной оси дают 0;
- герой не выходит за сужающиеся границы площадки;
- depth и безопасный масштаб героя зависят от Y;
- сборка проходит без ошибок.

## Контрольная точка перед M5

До M5 используются геометрические заглушки. Когда M4 завершён и базовый раунд работает на компьютере и планшете, Codex должен остановиться и напомнить владельцу проекта про проработку персонажей.

На этой точке нужно:

1. Составить короткий список героев и их ролей.
2. Выбрать одного героя для первого набора спрайтов.
3. Предоставить фотографии игрушек как референсы.
4. Согласовать оригинальный дизайн, который не копирует защищённого персонажа.
5. Подготовить `idle`, `walk`, `attack`, `hit` и `ko`.
6. Зафиксировать источники и лицензии в `docs/ASSETS.md`.

M5 меняет представление героя, но не боевую механику.

## Развитие голубого крылатого героя

Концепция зафиксирована в `docs/CHARACTERS.md`. Это дальнобойный мобильный герой со стрельбой и ограниченным полётом.

Последовательность:

1. В M5 создаётся только оригинальный внешний вид и базовые анимации, совместимые с уже готовым боем.
2. В M7.1 добавляется стрельба с cooldown.
3. В M7.2 добавляется ограниченный энергией полёт и автоматическое приземление.
4. В M7.3 герой включается в выбор персонажей, если playtest подтверждает ценность разных архетипов.
