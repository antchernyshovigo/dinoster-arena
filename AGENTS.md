# Dinoster Arena — инструкции для Codex

## Цель проекта

Сделать небольшую, отполированную и понятную ребёнку 2D-игру: один динозавр сражается с одним соперником на одной арене. Игра должна хорошо работать в браузере на компьютере и планшете в альбомной ориентации.

Главный критерий — ребёнку интересно играть уже в первый вертикальный срез. Расширять контент можно только после проверки этого среза.

## Зафиксированный стек

- Phaser 4.2.1.
- TypeScript 5.9.2 со строгой типизацией.
- Vite 7.1.0.
- Phaser Arcade Physics.
- Canvas/WebGL выбирает Phaser через `Phaser.AUTO`.
- npm и `package-lock.json`.

Не добавляй Three.js, React, Matter Physics, Unity, Godot, ECS-фреймворки или новый state manager без прямого запроса. Не обновляй зависимости попутно.

## Перед каждой задачей

1. Прочитай этот файл, `README.md` и релевантный раздел `docs/GAME_PLAN.md`.
2. Осмотри существующую реализацию и `git status`; не перезаписывай чужие изменения.
3. Сформулируй одну маленькую проверяемую цель и её критерии готовности.
4. Выполни `npm install`, если зависимостей ещё нет, затем `npm run build`.
5. Меняй минимальное число файлов. Не начинай следующий milestone в той же задаче.

## Первый вертикальный срез

В него входят только:

- одна арена;
- один управляемый герой и один простой AI-соперник;
- движение влево/вправо;
- одна обычная атака;
- здоровье, получение урона, KO;
- экран победы/поражения и рестарт;
- клавиатура и сенсорные кнопки;
- короткая обратная связь: вспышка попадания, небольшой screen shake, звук;
- раунд длительностью примерно 60–90 секунд.

Пока не входят: выбор персонажа, несколько динозавров и арен, комбо, уклонение, спецприёмы, онлайн, сюжетные сцены, инвентарь и прокачка.

## Архитектурные правила

- Сцены отвечают за жизненный цикл и связывание объектов, но не содержат всю игровую логику.
- Ввод преобразуется в намерения `moveX`, `attackPressed`, `restartPressed`. Игровой код не должен знать, пришло намерение с клавиатуры или touch UI.
- Состояния бойца: `idle | move | attack | hit | ko`.
- Атака проходит фазы `startup -> active -> recovery`.
- За одну атаку одна цель получает урон не более одного раза.
- Hurtbox — Arcade body бойца. Hitbox — временная Arcade zone, активная только в фазе `active`.
- Параметры скорости, здоровья, урона и таймингов хранятся в типизированных data-объектах, а не разбросаны по сцене.
- UI получает состояние через события или явный read-only snapshot; он не управляет физикой напрямую.
- Создавай новые папки и абстракции только тогда, когда они понадобились текущему milestone.

Предпочтительное направление структуры:

```text
src/
  actors/
  ai/
  combat/
  data/
  game/
  input/
  scenes/
  ui/
```

## Управление и экран

- Логический размер игры: 1280×720, масштабирование `Phaser.Scale.FIT`.
- Основной режим планшета — landscape.
- Минимальная интерактивная область touch-кнопки — 64×64 CSS px; между кнопками оставляй зазор.
- На первом срезе достаточно лево, право и одна кнопка атаки.
- Одновременное движение и атака должны работать через multi-touch.
- Русский UI должен быть коротким и читаемым без мелкого текста.
- Не привязывай игровой баланс к FPS; используй `delta`, таймеры Phaser или физику.

## Ассеты и авторские права

Репозиторий публичный. Не добавляй кадры мультфильма, музыку, логотипы, модели или спрайты правообладателя без явного разрешения и зафиксированной лицензии. Для разработки используй геометрические заглушки либо оригинальные/лицензированные ассеты. Для каждого внешнего ассета сохраняй источник и лицензию в `docs/ASSETS.md`.

Проект `dinoster-3d-model-lab` — отдельная лаборатория. Не копируй из него Three.js-код и GLB-модели в эту игру автоматически.

## Контрольная точка персонажей

Перед началом M5 остановись и явно напомни владельцу проекта, что пора:

- утвердить состав первого набора персонажей и их игровые архетипы;
- собрать фотографии игрушек только как визуальные референсы;
- выбрать одного героя для первого art pass;
- сгенерировать оригинальные изображения и анимационные листы, не копирующие защищённый дизайн;
- зафиксировать происхождение и лицензию каждого итогового ассета в `docs/ASSETS.md`.

Не начинай генерацию или добавление изображений без отдельного подтверждения владельца проекта. Фотографии игрушек не коммить в публичный репозиторий без явного разрешения.

Концепции и будущие способности хранятся в `docs/CHARACTERS.md`. Стрельба, полёт и выбор нескольких героев не входят в M5 и реализуются только в этапах M7 после проверки базового раунда.

## Проверка изменений

Обязательно:

1. `npm run build`;
2. ручной smoke test в браузере при 1280×720;
3. ручной smoke test в landscape-размере планшета, например 1024×768;
4. проверить отсутствие ошибок в консоли;
5. проверить, что canvas не прокручивает страницу и не перехватывает жесты браузера неожиданно.

Для боевой логики выноси чистые функции, чтобы позже добавить unit-тесты. Не добавляй тестовый фреймворк, пока не появится первая такая функция.

## Готовность задачи

В конце сообщи:

- что изменено;
- какие команды и сценарии проверены;
- что не проверено;
- известные ограничения;
- ровно один рекомендуемый следующий шаг.

Если сборка или smoke test не прошли, задача не считается завершённой.
